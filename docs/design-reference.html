Floodlit LED

A T20 night match. Stadium dark, and the one thing that is live on the page is genuinely lit while everything else sits quiet. This file is the source of truth for exact values — read its CSS rather than re-deriving anything.

Token naming

shadcn/ui semantic names are the interface, because every shadcn component references them. Renaming them would mean rewriting each component. The concept names map onto those:

--background → the page  ·  --card → a card face
--foreground / --muted-foreground / --subtle-foreground → three tiers of text
--secondary / --accent → raised and hover surfaces
--border → every hairline

Additions shadcn has no equivalent for: --live, --live-foreground, --settled, --bloom, and --subtle-foreground for a third text tier.

Buttons

The primary button is near-white, not blue. A primary action is not a live state, so rule 1 forbids the accent here. A light fill on a dark surface is the standard pattern and reads as clearly primary.

Rule 5 — a card or row body is itself the link. Buttons are reserved for secondary actions.

The signature element

The bloom on a live card — a radial gradient from the top edge plus a two-pixel beam that pulses. Rule 3: one per screen, maximum. Two glowing things compete and neither reads as important. Rule 4: the beam stops under prefers-reduced-motion, but the card still reads as live.

Because nothing else on the page uses --live, this lands without needing to shout.

The six rules

  1. --live appears nowhere except live states. Not primary buttons, not the brand, not active tabs, not badges, not league-type tags. This rule is the whole design — everything else exists so that this one lands.
  2. --settled for steady positive states — a gameweek running, points confirmed. Positive but not urgent.
  3. Bloom, not glow-everything. One lit element per screen, maximum.
  4. prefers-reduced-motion kills the beam, retaining static opacity. The state survives without the movement.
  5. The card or row body is the link. Buttons are for secondary actions.
  6. Mobile is the primary target. Every layout must survive 390px with no horizontal scroll.
